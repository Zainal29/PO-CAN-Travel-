Rombak ulang dan poles TOTAL UI homepage PO CAN Travel yang sekarang.

Fokus pada **layout, warna, spacing, typography, hierarchy, navbar, hero, search form, jadwal, tombol, footer, dan responsive**.

**Jangan mengubah backend, database, migration, controller, service, auth, middleware, route, atau business logic.**

## URUTAN KERJA — WAJIB

**Jangan langsung edit.**

### 1. AUDIT

Baca terlebih dahulu:

* `routes/web.php`
* `resources/views/welcome.blade.php`
* controller homepage
* `SearchTripRequest`
* Customer Trips Controller/View
* `TravelRoute`
* `Bus`
* `resources/css/app.css`
* `resources/js/app.js`

Pahami variable, route, form, dan data yang tersedia. Jangan menebak nama variable.

### 2. PETAKAN UI

Identifikasi bagian homepage saat ini:

* Navbar
* Hero
* Search
* Jadwal
* Benefit
* Cara Booking
* CTA
* Footer

Tentukan bagian yang dipertahankan, dirombak, dipoles, atau dihapus.

### 3. TENTUKAN DESIGN

Gunakan **biru + putih + slate**.

Referensi warna:

* Primary `#2563EB`
* Dark `#1E3A8A`
* Light `#EFF6FF`
* Background `#F8FAFC`
* Text `#0F172A`
* Secondary `#64748B`
* Success `#16A34A`
* Warning `#F59E0B`

Boleh menyesuaikan shade agar harmonis.

### 4. RENCANA LAYOUT

Target:

`Navbar → Hero + Search → Jadwal Bus → Cara Booking → Benefit/Info → CTA → Footer`

Jangan menambah banyak section hanya untuk memperpanjang halaman.

### 5. IMPLEMENTASI

### NAVBAR

Clean, putih, sticky, border tipis.

Guest:
`Jadwal Bus | Masuk | Daftar`

Customer:
`Jadwal Bus | Beranda | Pesanan | Profil`

Admin:
`Jadwal Bus | Kembali ke Admin`

**Admin tidak boleh diarahkan ke `/customer/*`.**

### HERO

Buat seperti website resmi perusahaan bus/travel.

* Visual/foto bus yang relevan
* Headline kuat
* Deskripsi singkat
* Feature kecil
* Search menjadi focal point

Gunakan background image jika asset tersedia.

**Jangan penuh gradient.**

Search card:

* putih
* border
* shadow ringan
* radius moderat
* terlihat seperti booking widget profesional

### SEARCH

Gunakan field dan route dari backend yang SUDAH ADA.

Minimal sesuai `SearchTripRequest`:

* Asal
* Tujuan
* Tanggal
* Penumpang
* Tipe bus/filter lain yang memang tersedia

Jangan membuat field atau backend baru.

### JADWAL BUS

Gunakan data database, **jangan hardcode**.

Buat card terasa seperti tiket:

```text
07:30
Jepara
Terminal Jepara
       │
       │
Semarang
Terminal Semarang
09:30

PO CAN Travel · Executive
26 kursi tersedia

Rp75.000       Lihat Detail
```

Tampilkan data yang memang tersedia:

* tanggal
* jam
* asal/tujuan
* terminal
* bus
* tipe
* kursi
* harga
* status

Tambahkan konteks waktu berdasarkan `departure_date + departure_time`:

* Berangkat hari ini
* Berangkat besok
* Berangkat dalam X jam
* Perjalanan telah dimulai
* Keberangkatan telah lewat

Gunakan timezone `Asia/Jakarta`.

**Jangan tambah database field.**

### CARA BOOKING

Buat alur visual:

`01 Cari → 02 Pilih Kursi → 03 Isi Data → 04 Bayar → 05 E-Ticket`

Desktop horizontal, mobile responsive.

### BENEFIT / INFO

Poles section yang sudah ada:

* Pilih Kursi
* Pembayaran
* E-Ticket QR

Gunakan informasi yang benar-benar didukung sistem.

### CTA

Sederhana:

**Siap berangkat?**

Cari jadwal bus dan pesan perjalanan Anda sekarang.

`Cari Jadwal`

### FOOTER

Dark navy/blue, compact dan profesional.

PO CAN Travel + deskripsi + link:

* Jadwal
* Cara Booking
* Pesanan
* Kebijakan
* Kontak

Jangan membuat form kontak/social media palsu.

## STYLE — HINDARI AI SLOP

Jangan gunakan:

* gradient berlebihan
* glassmorphism
* blob
* floating card berlebihan
* shadow besar
* terlalu banyak rounded card
* icon besar di setiap bagian
* terlalu banyak badge
* heading raksasa
* semua elemen dibuat card
* whitespace berlebihan
* tampilan SaaS/AI startup

Gunakan layout yang natural, clean, cerah, dan profesional seperti website booking bus sungguhan.

Tidak semua section harus memiliki struktur card yang sama.

## RESPONSIVE

Optimalkan:
`360 / 390 / 430 / 768 / 1024 / 1280px`

Mobile harus benar-benar dirancang ulang, bukan sekadar mengecilkan desktop.

Pastikan tidak ada horizontal overflow.

## LARAVEL

Jangan hardcode:

* harga
* jadwal
* bus
* kursi
* kota
* status

Jangan query database dari Blade.

Fokus perubahan:

* `resources/views/welcome.blade.php`
* `resources/css/app.css` jika diperlukan

## ROLE & SECURITY

Jangan mengubah middleware untuk mengatasi masalah UI.

Customer tetap hanya customer.

Admin tetap admin.

Jika admin membuka homepage public, tampilkan **Kembali ke Admin**, bukan dashboard customer.

## VALIDASI

Setelah selesai:

```bash
php artisan optimize:clear
php artisan view:cache
php artisan test
npm run build
```

Jika error, perbaiki penyebab yang relevan. Jangan melakukan refactor backend besar-besaran.

Sebelum selesai pastikan:

* Layout benar-benar lebih menarik dari sebelumnya.
* Biru-putih konsisten.
* Tidak penuh gradient.
* Tidak terlihat AI slop.
* Search menjadi focal point.
* Jadwal mudah dibaca.
* Mobile nyaman.
* Semua data tetap dinamis.
