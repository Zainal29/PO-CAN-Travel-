# ENTITY RELATIONSHIP DIAGRAM (ERD)

## 1. Database Entities

Database utama PO CAN Travel terdiri dari:

1. `users`
2. `buses`
3. `routes`
4. `orders`
5. `order_details`
6. `payments`

### Laravel Model Naming

Karena Laravel memiliki facade:

```php

```

model database `routes` menggunakan:

```text
TravelRoute
```

dengan:

```php

```

Nama tabel database tetap:

```text
routes
```

# 7. order_details

Fields:

```text
id                BIGINT PK
order_id          BIGINT FK
passenger_name    VARCHAR
passenger_phone   VARCHAR
passenger_email   VARCHAR NULL
seat_number       VARCHAR
price             DECIMAL(12,2)
created_at        TIMESTAMP
updated_at        TIMESTAMP
```

Relationship:

```text
order_details N:1 orders
```

Important:

`seat_number` tidak boleh dibuat globally unique karena nomor kursi yang sama dapat digunakan pada perjalanan yang berbeda.

Validasi kursi dilakukan berdasarkan perjalanan/order dan proses booking transactional.

# 10. Delete Rules

```text
buses → routes
RESTRICT

users → orders
RESTRICT

routes → orders
RESTRICT

orders → order_details
CASCADE

orders → payments
CASCADE
```

Soft delete digunakan pada:

```text
users
buses
routes
orders
```

---

# 11. Important Database Rules

1. `users.email` unique.
2. `buses.bus_code` unique.
3. `buses.plate_number` unique.
4. `orders.order_code` unique.
5. `payments.order_id` unique.
6. `order_details.seat_number` tidak global unique.
7. Harga order harus berasal dari harga route di database.
8. `available_seats` harus diperbarui secara transactional.
9. Double booking harus dicegah.
10. Foreign key wajib digunakan.
11. Soft delete wajib digunakan pada entity yang telah ditentukan.
